# Pictogram
A compile time friendly svg icon catalogue.

Every icon is a plain `const`. There is no macro and no build script, and only the icons you use end up in your binary.

```rust,ignore
const HOME: pictogram::Svg = pictogram::lucide::house::outlined;
```

## Features
* **Compile time friendly**: The whole catalogue compiles in well under a second. Features only save the download.
* **Type-safe**: An icon that does not exist is a compile error, and your editor completes the names.
* **Const**: Icons can be assigned to `const` and `static` items.
* **Drawn correctly**: The icon keeps its `fill`, `stroke`, ... so outline icons stay outline icons. Icons use `currentColor` and follow the text color.
* **Framework independent**: [`pictogram-core`](pictogram-core) has no dependencies. There is an [adapter for dioxus](pictogram-dioxus).
* **Always up to date**: A workflow checks for new releases of the icon libraries and opens a pull request. Icons that were renamed upstream stay available under their old name as deprecated aliases.

## How to use it
```toml
[dependencies]
pictogram = "0.4"
```

```rust,ignore
let svg = pictogram::lucide::house::outlined;
println!("{svg}"); // <svg xmlns="..." viewBox="0 0 24 24" fill="none" stroke="currentColor" ...>...</svg>

// Icons are data
svg.view_box; // "0 0 24 24"
svg.attrs;    // the attributes of the root element
svg.body;     // everything inside of it
```

Your own icons are parsed by the compiler:
```rust,ignore
const CUSTOM: pictogram::Svg = pictogram::Svg::new(include_str!("custom.svg"));
```

### Dioxus adapter
```rust,ignore
use pictogram_dioxus::Pictogram;

rsx! {
    Pictogram {
        icon: pictogram::lucide::house::outlined,
        width: "3rem",
        height: "3rem",
        color: "red",
    }
}
```
See [pictogram-dioxus](pictogram-dioxus) for more.

By default all libraries are enabled. Every library has a feature of the same name to save the download of the ones you do not use.
Enabling all of them costs well under a second of compile time.

## How it works
* Every `pictogram-icons-*` crate is generated by `cargo xtask update <library>` from a release of the upstream project (Material, which does not tag releases, from the tip of its default branch): one `pub const` per icon, and the path (`house::outlined`) is the index.
* Hard coded colors (Heroicons, Ionicons) are replaced by `currentColor`, so every icon follows the text color.
* The update workflow is [`.github/workflows/update-icons.yml`](.github/workflows/update-icons.yml). It runs `cargo xtask update <library>`, which fetches the latest release of the upstream project, regenerates the crate and bumps its version (patch if icons were added, minor if icons were removed). To update by hand:
  ```sh
  cargo xtask update lucide            # the latest release
  cargo xtask update lucide --version 1.8.0
  cargo xtask generate lucide --source <checkout> --version 1.8.0   # from a checkout, offline
  ```
